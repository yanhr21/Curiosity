# Plan-10 articulated five-finger foundation result

Date: 2026-08-01

## Conclusion

The old fixed-rubber-hand tactile branch is not force-balanced tactile. Its
world motion is generated by valid underlying PhysX contacts, but only a few
distal regions actually carry the box and the integrated TacSL field does not
reconstruct those object dynamics. It is retained only as a negative control.

The replacement physical foundation is now real and executable: the exact
official Unitree G1-29+Inspire asset loads in the current IsaacLab/Isaac Sim
runtime, exposes independently articulated five-finger hands on both sides,
and passes a synchronized full-body/bilateral-hand motion video gate. This is
not yet a CarryBox or tactile result.

## Why the old display looked empty

The V87 middle frame has 54 declared patches but only six raw-loaded patches:
left index/middle/ring/little distal and right ring/little distal. Palm center,
thumb, every middle/proximal finger surface and most palm surfaces are unloaded
in that frame. This is not a plotting-density problem. It follows from using
one rigid rubber hand whose rendered fingers cannot independently conform to
the box.

The force audit separates two questions:

- Raw PhysX contact versus object dynamics: dynamic force residual median
  `0.1531605` and torque residual median `0.0295983`, both within the frozen
  `0.20` boundary.
- Integrated TacSL versus object dynamics: force residual median `3.8880633`
  and torque residual median `0.4802201`, both outside the boundary. There are
  zero qualifying quasi-static support frames, so the gravity-support gate is
  also false.

Therefore the precise answer is: the simulator's hidden/raw contacts largely
explain the moving box, but the alleged whole-hand tactile force balance is not
satisfied. A complete-looking lift video cannot repair that discrepancy.

## 2026-08-02 no-learning CarryBox result

The articulated asset is valid, but the physical CarryBox installation gate
is still negative. The strongest pure topology run (V115) holds all six
anatomical groups on both hands for `664` frames yet lifts only `0.007224 m`.
The strongest unanchored apparent rises plateau near `0.049 m`; exact trace
inspection shows about `0.133 m` horizontal box drift and `0.27 rad` rotation.
When V155 makes the hands resist that drift, named non-hand load becomes
exactly zero but lift falls to `0.014124 m`. The current asymmetric
"bottom-support" V156 reaches only `0.010583 m`, never establishes bilateral
all-six-group load, then loses the box.

This answers the force-balance question directly: a whole hand can surround
the object visually while only a few links provide instantaneous load, and the
current traces do not contain a hand-only stable interval above `0.10 m` on
which the frozen raw force/torque balance can pass. No tactile result is
claimed and no 27-patch sensor has been attached.

## Deformable tactile status

Official Taccel commit `cb23bc251b531ba6908a3788c2f91423cd543149`
(MIT) remains the primary soft-gel source. Its unchanged soft-teddy example
passes 80/80 CUDA/IPC solver steps at one and four environments. Those runs do
not prove tactile response: all saved PLY frames are bitwise identical and no
RGB, depth or marker stream is saved.

The released TacMan path does call `render_tactile()`, but the pinned compiled
runtime fails at the first solver step because conjugate-gradient scatter gets
16 indices for 14 source rows. That is a compatibility blocker, not permission
to generate taxels or substitute a toy renderer. No deformable tactile result
is admitted.
